## บทเรียน

1. **Exit code ของ background task ที่มี pipe คือของคำสั่งสุดท้าย ไม่ใช่คำสั่งหลัก** — deploy ผ่าน ssh ต้องเห็น exit code จริง (echo มันออกมา หรือ set -o pipefail) ไม่งั้น build ล้มแล้วเข้าใจว่าผ่าน → learning แยกบันทึก
2. **Smoke test ก่อนติดตั้ง automation ไม่ใช่ขั้นตอนทางการ** — ถ้าติดตั้งตาม runbook ตรงๆ cron จะรันแบบเงียบผิดทุก 30 นาที (แต่ exit 0 ทุกครั้ง)
3. **Runbook ที่เขียนไว้เองก็หลอกเราได้** — env var ใน runbook ดูสมเหตุสมผลแต่โค้ดไม่เคยอ่านมัน (compose-env-no-op class ที่เจอมาแล้วใน ISSUE-100) — การ verify ต้องเป็นการรันจริง ไม่ใช่เชื่อ comment
4. **Dependency gate ของ compose เป็น safety net ที่ดี** — mt5b/c/d ติดอยู่ใน Created ไม่มีใครสังเกต แต่ up -d เตือนเอง; อนาคตควร `docker compose ps -a` ใน pre-deploy check

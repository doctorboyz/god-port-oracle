# ISSUE-104: watchdog ยิง alert ตลอดที่ตลาดปิด + ISSUE-108 ปิดตาม draft

## อาการ (จาก watchdog.log จริง)

feed-stale ALERT สะสม **326 ครั้ง** ใน 10 วัน ล้วน calendar noise:
เสาร์ 95/วัน, อาทิตย์ 89-95, วันธรรมดา 3-4/วัน (ตรง maintenance break
พอดี), ศุกร์เย็น ~10 — บวก self-error 2 ครั้ง (docker ps/logs failed)
ที่ถูกเขียนเป็น farm alert ตามที่ ISSUE-104 บ่นไว้

## จุดตัดสินสำคัญ: ปฏิทินที่หมอพิมพ์มา vs หลักฐาน feed จริง

หมอสั่ง "Sun 23:00 → Fri 22:00 UTC, maintenance 22:00-23:00" (คัดลอกจาก
Hermes) แต่หลักฐานที่หมออ้างเอง — แท่งสุดท้ายศุกร์ 20:55 UTC — บอกว่าปิด
21:00 UTC จริง ตรวจ feed ยืนยัน: แท่งแรกอาทิตย์ 22:00 UTC, break รายวัน
21:00-22:00 (alert 21:39/21:54/22:09 วันจันทร์ที่ bar หยุดตอน 21:00)
= ชั่วโมง CDT (UTC-5) ส่วนที่หมอพิมพ์คือ CST (UTC-6, ใช้หลัง 1 พ.ย.)

**ถ้า hardcode ตามตัวเลขที่พิมพ์** watchdog จะ false-alert ทุกวันธรรมดา
21:00-22:00 UTC (~20 ครั้ง/สัปดาห์) — ขัดเป้า "alert เหลือ 0" — เลย
implement เป็นชั่วโมงจริงของ CME แบบ **Chicago-local DST-aware**
(zoneinfo): วันนี้ตรงหลักฐานเป๊ะ หลัง 1 พ.ย. กลับเป็นชั่วโมงที่หมอพิมพ์
เองโดยไม่ต้องแก้โค้ด — single source of truth อยู่ที่
`shared/market_calendar.py` Hermes import รอบหน้า

## สิ่งที่แก้

1. **Feed gate** (ISSUE-104): `check_feed` ข้ามทั้งหมดเมื่อ `market_open()`
   = False — ตลาดปิด = feed stale เป็นเรื่องปฏิทิน ไม่ใช่ปัญหา farm
2. **Self-error แยกช่อง** (ISSUE-104 ต้นฉบับ): docker CLI fail →
   `SELF-ERROR:` prefix → log-only ไม่แตะ alert channel, ไม่ advance
   regression state (ช่วงที่สแกนไม่ได้ต้องสแกนซ้ำรอบหน้า), exit 2 แยกจาก 1
3. **Alert ที่เหลือตรวจแล้วไม่ใช่คลาส false-positive**: container +
   regression ไม่ผูกกับเวลาตลาด (container ต้อง Up ตลอด, pattern
   regression ต้องมี bar ถึงเกิด) — หลักฐาน: 0 false positive ในประวัติ 326
4. **ISSUE-108** (หมออนุมัติ "ทำต่อได้เลย อย่าลบ draft"): portfolio_manager
   อ่าน `TG_*` ก่อน fallback `TELEGRAM_*` ตาม pattern pf_monitor

## บทเรียน

- **ปฏิทินตลาดต้องเก็บใน timezone ของตลาด ไม่ใช่ UTC ตายตัว** — CME
  ประกาศเป็นเวลา Chicago และเลื่อนตาม DST; hardcode UTC ถูกครึ่งปีเสียครึ่งปี
- **เวลา test ผูก wall clock จริง = time bomb** — suite รันวันเสาร์กับวันพุธ
  ให้ผลต่างกัน ต้อง pin เวลาเสมอ (คลาสเดียวกับ env รั่ว RANGING_HARD_BLOCK
  รอบก่อน)
- หลักฐานล้วนๆ (แท่งสุดท้าย, แท่งแรก) ตัดสินชั่วโมงที่คำสั่งพิมพ์ผิดได้ —
  ถามข้อมูลก่อน แล้วเลือกแบบที่ตรงทั้งสองฤดู

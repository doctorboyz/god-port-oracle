## Architecture Decisions

### Decision 1: ปิด ML บน Real-A ที่ $400
- **เลือก**: no-ML (AEGIS-only) แทน v4 single @0.55
- **ทำไม**: Backtest premium $500 no-ML MaxDD 20.2% อยู่ในเลขปลอดภัย ส่วน ML ลด MaxDD เหลือ 8.6% แต่ PnL หายไป 50% — ส่วนต่าง PnL สูญเปล่า
- **ขัดแย้งกับ** learning ก่อนหน้าที่แนะนำ v4 สำหรับ $100-$500 → แต่ $400 baseline ที่ปลอดภัยแล้วทำให้ break-even point เปลี่ยน

### Decision 2: คืน good-era kill switch (5/10/20)
- **เลือก**: 5% daily / 10% weekly / 20% account (แทน 20/30/30 ที่หลวมเกิน)
- **ทำไม**: no-ML MaxDD สูงกว่า ML → ต้อง halt เร็วกว่ากัน ruin บน $400 balance
- **Trade-off**: อาจ halt เกินจำเป็นในบางจังหวะ → แต่ capital preservation > profit (Principle 7)

### Decision 3: Manual withdrawal ไม่ใช่ auto
- **เลือก**: user ถอนเองผ่าน Exness terminal ถ้า balance ≥ $500
- **ทำไม**: ไม่มี auto-withdraw API และการเชื่อม Exness withdrawal เข้าระบบเพิ่ม attack surface + risk
- **Protocol**: ≥$500 → ถอน $100 → คง $400 | ≥$600 → ถอน $200 | ≥$800 → ถอน $400

## Honest Feedback (100+ words, 3 friction points)

1. **smoke-test-ml.py path mismatch เป็น latent bug ที่ผมปล่อยไป** — ผมเห็น fail แต่ rationalize ว่า "ไม่ใช่ blocker" ทั้งที่จริง ๆ มันน่าจะแก้สักที เพราะทุกครั้งที่ deploy จะเห็น error เดียวกัน ผมเก็บไว้เป็น issue แล้วดีกว่า ไม่ใช่ rationalize ผ่าน

2. **ผม query SQL ผิดซ้ำ ๆ ในเรื่อง schema** — `equity` column ไม่มี, `volume` vs `lot_size`, `account_id` vs `id` ทั้งที่มี learning doc `2026-06-28_db-schema-reference` อยู่แล้ว ผมไม่ได้เปิดอ่านก่อนทุกครั้ง — นี่คือการไม่ใช้ memory ที่ตัวเองเขียนไว้ น่าผิดหวัง

3. **ผมเสียเวลากับ output flooding (PerformanceWarning 5000+ บรรทัด)** — แทนที่จะ filter output ตั้งแต่แรก ผมปล่อยให้ context ถูกกินแล้วค่อย grep ทีหลัง — ควร set `python -W ignore::PerformanceWarning` หรือ pipe ผ่าน `grep -E` ตั้งแต่แรก

## Lessons Learned

1. **ML filter ไม่ใช่ free lunch** — บน balance ที่ survival ปลอดภัยแล้ว ($400+ with good-era kill switch) การเปิด ML = เสีย PnL สูงกว่าค่า survival ที่ได้
2. **Withdrawal = active risk management** — ถอนกำไรเรื่อย ๆ เพื่อล็อค MaxDD % ไม่ให้โตตาม balance — กลไก user-side นอกจาก DP/CB ในระบบ
3. **Top-up sequence สำคัญก่อน deploy** — verify MT5 equity จริง ๆ ก่อนอัปเดต `INITIAL_EQUITY_A` ไม่ใช่ trust .env
4. **Decision rule เปลี่ยนตาม equity** — $100-$200 → ML on (survival-critical), $400+ → no-ML (profit-optimal) — recommendation ไม่ควรตายตัว
5. **Memory docs มีไว้อ่าน** — ถ้าเขียน learning doc ไว้แล้วไม่เปิดอ่านก่อนใช้ มันไร้ค่า

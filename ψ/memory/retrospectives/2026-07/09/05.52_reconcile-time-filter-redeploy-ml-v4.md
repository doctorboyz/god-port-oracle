## Key Code Changes

**Bug fix — Strategy 1 time guard** (applied in both `_match_closing_deal` and `_reconcile_external_close`):

```python
# Find OPEN deal time — closing deal must come AFTER
open_deal_time: float | None = None
if ticket is not None:
    ticket_int = int(ticket)
    for deal in deals:
        deal_order = deal.get("order")
        if deal_order is None or int(deal_order) != ticket_int:
            continue
        if deal.get("type", -1) != opening_type:  # OPEN has opening direction
            continue
        deal_time = deal.get("time")
        try: open_deal_time = float(deal_time)
        except (TypeError, ValueError): continue
        break

# Strategy 1: filter by time
if open_deal_time is not None:
    deal_time = deal.get("time")
    if deal_time is None: continue
    if float(deal_time) <= open_deal_time: continue  # BEFORE open — skip
```

**docker-compose separation** — `ML_FILTER_ENABLED_A` for oracle-engine (Real-A), `ML_FILTER_ENABLED` for oracle-engine-train (B/C/D). Independent toggles.

## Architecture Decisions

1. **OPEN deal identification without position_id**: Bridge doesn't expose `position_id`/`entry` fields, so use `deal.order == ticket` AND `deal.type == opening_type` to identify the OPEN deal. This gives us the open time without needing fields the bridge doesn't provide.

2. **ML config per-container via env var name**: Instead of changing the code to read `ML_FILTER_ENABLED_A` per-account (would require touching every trader), keep the code reading `ML_FILTER_ENABLED` and just give each container a different env var source in docker-compose. Zero code changes, deploy-time control.

3. **CPT with real production data**: Built causal test using the EXACT deals from Real-A 2026-07-07/08 (ticket numbers, prices, times). Test failing RED with real data is more convincing than synthetic mocks — proves the bug actually occurred, not just theoretically could.

## Lessons Learned

1. **Cross-check DB against source-of-truth before declaring "correct"** — DB exit_price must appear in MT5 deal history for that ticket. If not, something is wrong. Don't trust DB data I didn't reconcile.

2. **Strategy 1 (price proximity) without time filter is fundamentally broken** — any time multiple trades cluster in a price neighborhood, the algorithm will pick the wrong deal. Time guard is mandatory, not optional.

3. **Per-container env var separation in docker-compose is cleaner than per-account env var in code** — zero code changes, deploy-time control, no risk of breaking other accounts.

4. **Search existing issues before creating new ones** — `issue-tracker.py search <keyword>` exists. A 30-second search would have shown ISSUE-074 was already filed for this exact bug.

5. **CPT with real production data > synthetic mocks** — using the actual Real-A deals (ticket numbers, prices, times) in the causal test makes the bug undeniable. Synthetic data can always be dismissed as "wouldn't happen in practice."

## Honest Feedback (3 friction points)

1. **ผมเสียเวลา debug สิ่งที่ควรรู้อยู่แล้ว** — DB schema ของ project ตัวเอง ควร query PRAGMA ก่อนเขียน SQL ไม่ใช่เขียนแล้วแก้ column ผิดทีละตัว (action→direction, entry_time→timestamp, net_pnl→pnl, account_id='A'→1). มันเสียเวลา ~20 นาทีในสิ่งที่ avoid ได้. บทเรียน: verify schema before writing SQL.

2. **Shell quoting ยังเป็นจุดอ่อน** — ผมลอง inline `python3 -c "..."` กับ f-string ที่มี nested quotes และ unicode จนพัง 2 รอบก่อนเปลี่ยนเป็น heredoc. ผมควร default สู่ heredoc ทุกครั้งที่มี Python multi-line ใน shell. มันไม่ใช่เรื่องของ "รอให้พังก่อนแล้วค่อยแก้" — มันคือ default ที่ควรตั้งใจเลือก.

3. **Deploy ไม่มี automated test** — ผม deploy config + restart container แล้ว verify ด้วย grep logs. ถ้าวันจันทร์มี regression แบบ subtle (เช่น BUY signals ไม่ลด 30%, หรือ daily limit ไม่ enforce) ผมอาจไม่ทันสังเกต. ผมควรมี assertion script ที่ตรวจ "DrawdownProtector initialized with peak=200" และ "no BLOCKED messages in last 100 lines" แล้วรันเป็น cron. ตอนนี้พึ่ง human attention.

## Lessons Learned

- **Top-up sequence**: verify MT5 equity BEFORE updating INITIAL_EQUITY_A — ถ้า set ก่อน equity ถึง → peak > equity → BLOCKED
- **Good era config diffs**: only 2 values differ from broken era — DRAWDOWN_DAILY_LIMIT (0.20→0.05) และ BUY_MIN_CONFIDENCE (0.45→0.50). ไม่ใช่ config ทั้งหมดที่เปลี่ยน
- **Real vs ghost classification**: exit_reason field ใน DB แยกให้ — real = take_profit/stop_loss/max_holding/trailing_stop; ghost = closed_by_mt5_inferred/ghost_no_mt5_ticket_inferred
- **Shell heredoc default**: ใช้ `<< 'PYEOF'` สำหรับ Python ใน shell เสมอ, อย่าฝืน inline `python3 -c`
- **DB schema verification**: query PRAGMA table_info ก่อนเขียน SQL เสมอ, อย่าพึ่ง memory

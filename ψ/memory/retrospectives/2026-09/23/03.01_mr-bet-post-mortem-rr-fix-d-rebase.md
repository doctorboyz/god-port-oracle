## Honest Feedback

1. **ตรวจรับ deploy ตื้นเกิน**: ผมยืนยัน "env ครบแล้ว" จากการ echo os.environ ซึ่งเป็นการพิสูจน์ผิดระดับ — env ตั้งครบแต่โค้ดไม่อ่าน สองไม้แรกของการทดสอบเลยสะสมสถิติผิดแผน (RR 2.5) โดยที่รายงานคุณหมอตอนนั้นบอกว่า "ผ่านตรวจรับครบ" — ความผิดอยู่ที่เกณฑ์ตรวจรับของผมเอง ไม่ใช่ระบบ
2. **ชะล่ากับสัญญาณเตือนที่เห็นตั้งแต่แรก**: ตอน deploy ครั้งแรกเห็นแล้วว่า rr_ratio=2.5 ใน DB ไม่ตรงแผน 0.8 — ผ่านไป 2 วันกว่าจะกลับมาอ่านจริงจัง ถ้าคุณหมอไม่ถามเอง การทดสอบ dimension RR จะเสียไปทั้งชุดข้อมูล 4 สัปดาห์โดยไม่มีใครรู้

## Lessons Learned

1. **"Env ตั้งครบ" ≠ "config ถูกใช้"** — ตรวจรับ config ต้องอ่านค่าจากวัตถุที่ใช้จริง (instantiate trader แล้ว print risk.risk_reward_ratio) ไม่ใช่ echo os.environ
2. **host .env ชนะ ${VAR:-default} เสมอ** — ค่าที่ห้ามโดน override ต้อง hard-code ใน compose (pattern ที่ใช้แล้ว 2 ครั้ง: ML_FILTER_ENABLED, INITIAL_EQUITY_D)
3. Bug แบบ "สาขาที่ไม่เคยทำงาน" (`if not risk_config:`) มองไม่เห็นด้วย test ที่ mock ตามสมมติฐานว่า config มาทางเดียว — causal test ต้องสร้างตามเส้นทางที่ production ใช้จริง (runner ส่ง risk_config เสมอ)

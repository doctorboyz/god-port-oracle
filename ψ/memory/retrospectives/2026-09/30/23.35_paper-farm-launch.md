## Blockers & Resolutions

- **crontab ติดตั้งค้าง**: root helper ของ macOS crontab hang เมื่อถูกเรียกจาก process ที่ kill ได้แต่ตัวมัน kill ไม่ได้ → เปลี่ยนไป launchd LaunchAgent (`com.godport.farm-backup`) ทดสอบยิงจริงผ่าน; process ค้างตายเองภายหลัง
- **backup glob snowball**: `data/farm/*/*.db` จับ `data/farm/backup/` ตัวเอง → exclude backup dir ใน loop + ลบไฟล์ snowball + ยืนยันด้วยการรันจริง
- **SignalGroup "farm" ไม่มีใน enum**: ทุก variant ตายตั้งแต่ get_bridge_config → ใช้ "portfolio" + เพิ่มความรู้เรื่อง pydantic ValueError subclass

## Honest Feedback

1. **ผม retry เหมือนหวังให้มันหายเอง** — crontab hang 4 ครั้ง ทั้งที่หลักฐานบอกตั้งแต่ครั้งที่ 1 ว่าการเขียนคือปัญหา นี่คือการกระทำแบบ "ลองซ้ำแล้วค่อยคิด" ซึ่งเปลืองเวลาและสร้าง root process ค้าง 3 ตัวที่ต้องรอตายเอง บทเรียน: อาการเดิมซ้ำ 2 ครั้ง = เปลี่ยนวิธี ไม่ใช่ลองใหม่
2. **ผมแทบปล่อยให้บั๊ก backup ผ่านไป** — ถ้าไม่ยิง kickstart ทดสอบ launchd จริง glob snowball จะค่อยๆ กิน disk เงียบๆ ผมโชคดีที่ตัวเองตั้งใจ test plumbing จริง แต่นี่ควรเป็น step บังคับของทุก automation ไม่ใช่ความขยันเฉพาะวัน
3. **ผมจัด verification แบบเก็บไว้ท้าย** — แก้โค้ดหลายจุดแล้วไม่รัน suite จน Stop hook เตือน ทำให้ความเสี่ยงสะสมโดยไม่จำเป็น ถ้า suite fail ตรงไหนจะหาลำบากเพราะแก้ทับกันหลายจุด

## Lessons Learned

- macOS crontab ที่เรียกจาก non-interactive shell อาจ hang ที่ root helper (kill ไม่ได้) — launchd LaunchAgent คือทางที่เสถียรกว่าและ user-level (บันทึกเป็น learning แยก)
- glob pattern ที่ output dir อยู่ใน scope เดียวกันต้อง exclude ตัวเองเสมอ — backup job ต้องทดสอบ 2 วันติดกันถึงจะเห็น snowball
- ทดสอบ automation ด้วยการยิงจริง (kickstart + ดู output) ไม่ใช่แค่รัน script ตรงๆ
- pydantic ValidationError เป็น subclass ของ ValueError — enum ผิดจะกลืนไปกับ "Unknown account" ทำให้ root cause บัง

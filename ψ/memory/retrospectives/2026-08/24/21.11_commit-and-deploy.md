## Architecture Decisions

1. **Use live_trades only (no rejected_signals)** — user approved 2026-08-23. rejected_signals table is empty, adding it would inflate snapshot size without value.
2. **JOIN accounts WHERE name='D'** instead of hardcoding account_id=4 — D's account_id was observed as 4 today but could change if accounts table is rebuilt. Filtering by name is robust.
3. **Cumulative baseline starts 2026-08-23** — `exit_time > '2026-08-23'` filters out the pre-existing open SELL (ticket 3411173137, opened 2026-07-02) from cumulative PnL math.
4. **stdout redirect pattern for CSV/JSON** — Python in container can't write to host paths, so each `docker exec` prints to stdout and host bash redirects. Split into 2 separate exec calls (JSON + CSV) because merging them is harder than running two.
5. **CronCreate one-shot for auto-loop test, not /loop** — /loop is for iterative work within a session; CronCreate is the right primitive for "wake me up at 21:51 to test the wake mechanism".

I came into this session mid-thread — the prior conversation had already designed the Demo-D deploy. My job was to land it: write the cron script, push it to VPS, install crontab, verify, and document.

The script work was where I tripped. First version used multi-line SQL strings inside `python3 -c "..."` — Python's parser rejects newlines in `"..."` strings. I caught it only by running `bash -x` and finding `SyntaxError: unterminated string literal` in `query.err`. The fix was mechanical (collapse SQL to single-line + use bash single-quote outer with `'\''` inner escaping), but I burned 30 minutes on it.

The second stumble was assuming Python in the container could write to host paths. It can't — the container filesystem is isolated. `print()` to stdout + host redirect is the right pattern, and once I applied it the script worked first try. ## Lessons Learned

1. **`docker exec ... python3 -c "..."` requires single-line SQL strings** — Python parser rejects newlines in `"..."`. Use single-line SQL or `"""..."""` triple-quotes (harder with bash). [Saved to learning memory: 2026-08-23_demo-d-slow-but-sure-deploy.md]
2. **Python in container cannot write host paths** — must `print()` to stdout + host redirect. Each output = 1 separate `docker exec` call. [Saved]
3. **VPS `.env` overrides `docker-compose.vps.yml` `${VAR:-default}`** — compose default only applies when env var is unset. If `.env` has the var, compose default is ignored. Must edit both files.
4. **CronCreate jobs are session-only** — die when Claude session exits. The VPS crontab is the durable part; the Claude auto-loop is not. For true 24/7 auto-loop, need a different mechanism (e.g. `maw` or external scheduler that launches new Claude sessions).
5. **Snapshot pull scripts should use tmp staging during development** — write to `ψ/inbox/.staging/` first, move to `ψ/inbox/demo-d-snapshot-<TS>/` only when verified. Avoids leaving broken dirs from failed test runs.

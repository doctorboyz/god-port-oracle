## การค้นพบสำคัญที่สุดของรอบนี้ — โจทย์วินิจฉัย "รู 12 แท่ง 5/11" ผิด

โจทย์ T2 ตั้งสมมติฐานว่า fetcher stale ~65 นาที (5/11 22:00-23:00 UTC หลัง halt) ทำให้แท่ง M5
หายถาวร 12 แท่ง (22:00-22:55) เป็นรูใน indicator history และสั่งให้ "อุดรูครบ 12 แท่ง" —
**หลักฐานจริงหักล้างทั้งหมด 4 ข้อ:**

1. **รู 22:00-22:55 มีทุกวัน** — ตรวจ CSV จริง 2/11, 3/11, 4/11, 5/11 เหมือนกันหมด (กระโดด 21:55 → 23:00)
   และ H1 ก็ไม่มีแท่ง 22:00 เหมือนกันทุกวัน — ไม่ใช่อุบัติเหตุเฉพาะ 5/11
2. **ก่อน DST (28-29/10) รูอยู่ที่ 21:00-21:55** — พอ US DST จบ (1/11/2026) รูเลื่อนไป 22:00-22:55
   พอดี +1 ชม. ตรงตามที่ retro 30/10 เตือนไว้ ("ตรวจซ้ำหลัง DST 1/11")
3. **bridge ไม่มีแท่งนั้นให้อุด** — probe read-only (copy_rates 700 แท่ง ครอบ 11-04→11-06):
   แท่งช่วง 22:00-22:55 ของ 5/11 = **0 แท่ง** แต่ช่วง 21:00-21:55 (slot halt ก่อน DST) = 12 แท่ง
   คือ broker เองก็ไม่มี เพราะตลาดปิดจริง
4. **fetcher ไม่ได้ตายช่วงนั้น** — log ดิบ 5/11 21:59-23:06 UTC มี 75 บรรทัด "no new bars"
   ทุก 60s ตลอด (ครั้งแรก grep มาผิด ทำให้เข้าใจว่าเงียบ) — bridge ตอบปกติ แค่ไม่มีแท่งใหม่

**สรุป: 22:00-22:55 UTC ของ 5/11 คือช่วง halt ประจำวันที่เลื่อนตาม DST ไม่ใช่ข้อมูลหาย**
การ "อุดรู" ด้วยการปลอมแท่งขึ้นมา 12 แท่ง = ปลูก gap ปลอมใน indicator history ทั้งฟาร์ม
(ผิดจิตวิญญาณกฎห้าม mix feed เดียวกัน) — งานนี้จึง**ไม่อุด และรายงานกลับพร้อมหลักฐาน**
แทนที่จะทำตามโจทย์แบบไม่ถาม อินดิเคเตอร์มอง gap นี้เหมือน overnight gap ปกติที่มีทุกวัน

## T2 — backfill แท่งที่หายหลัง stale จริง (ปัญหาคลาสจริงที่ยังมีอยู่)

แม้รู 5/11 ไม่ใช่รู คลาสปัญหาในโจทย์ยังจริง: **fetcher ล่มนานเกิน delta window (300 แท่ง M5
≈ 25 ชม. trading) → แท่งที่ bridge มีแต่เก่ากว่า window จะไม่มีวันถูก merge อีก = รูถาวร**
(heal ได้ทางเดียวคือ restart ที่ seed 15,000 แท่ง)

แก้ที่ `scripts/paper_feed_fetcher.py`: `_backfill_stale_gap()` — ทุก poll (bridge mode) เทียบ
แท่งสุดท้ายใน store กับหน้าต่าง delta ที่ fetch มา ถ้าหน้าต่างไม่ย้อนถึง tail = รอยต่อขาด →
re-fetch ลึกพอครอบ [tail → now] จาก **bridge ตัวเดิม** (read-only เท่านั้น ไม่มี yfinance
ไม่มี mix) แล้ว merge เรียงเวลา dedupe ตาม timestamp — false-positive free เพราะ
หน้าต่าง delta ทับ tail เสมอทั้งกรณีปกติ/halt ประจำวัน/weekend

- **Causal tests RED→GREEN**: `TestBridgeBackfillCausal` 3 ตัว (gap กลาง → insert ครบเรียงเวลา ·
  ไม่มี gap → ไม่ยิง deep fetch · duplicate guard) — RED ยืนยันสาเหตุตรง: รู 05:00-06:55
  รอดทุก poll ก่อน fix
- **พิสูจน์บนข้อมูลจริง**: สำเนา CSV จริง ตัดแท่ง 5/11 12:00 → 6/11 21:55 (395 แท่ง) รัน 1 poll
  กับ bridge จริง → ตรวจจับ gap ("delta window starts at 20:00 but store tail is 12:00")
  อุดกลับมา **395/395 แท่ง OHLCV ตรงต้นฉบับเป๊ะ** เรียงเวลา ไม่มีซ้ำ
- **ชุดจริงที่ไม่โดนแตะ**: รัน 1 poll กับ store จริง = "no new bars" ไม่มี gap ให้อุด (store
  contiguous กับ bridge อยู่แล้ว)

   แท่ง M5 ต้องไหลเข้า store ตามปกติ (fetcher โค้ดใหม่ deploy แล้ว)
